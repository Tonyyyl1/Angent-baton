# relay-desk 双机接力

## 什么时候用

- 用户要离开这台电脑，到另一台继续做（「接力」「交接」）。
- 用户在另一台电脑上接手（「接棒」「接手」）。
- 用户问台账或项目进度（「台账」「接力状态」）。
- 日常开工、收工，或工作区有变化。

台账是一个 JSON 文件，由命令行 `{{RELAY}}` 读写。Claude Code 和 Antigravity 也用这份台账：它们登记的 Session 和备注这里都能看到，反过来也一样。

命令一律写成 `{{RELAY}} …`，原样保留，不要改写。项目名省略时，取当前目录所在的项目。

## 平时

- 开工：先运行 `{{RELAY}} status`。
- 收工：运行 `{{RELAY}} note <项目> --last "最近做了什么" --next "下一步"`。
- 工作区有变化（改文件、提交、切分支）：运行 `{{RELAY}} scan <项目>`。

## 离开这台设备（「接力」「交接」）

1. 运行 `{{RELAY}} handoff <项目>`。它打印离开清单。如果提示项目不在本机，停下来告诉用户。
2. 逐项完成清单：
   - 写或更新项目里的 `HANDOFF.md`，写入摘要：做了什么、停在哪、下一步、怎么验证。只写文件，不替用户提交或推送。
   - 运行 `{{RELAY}} note <项目> --last … --next … --verify <none|pass|partial|fail>`，记下最近任务和下一步。
   - 运行 `{{RELAY}} session add <项目> latest --tool codex`，登记当前线程。
3. 按下一节处理清单里的命令块。
4. 每完成一项，运行 `{{RELAY}} check <项目> pre <key>`。
5. 全部完成后，运行 `{{RELAY}} depart <项目>`。

## 到达这台设备（「接手」「接棒」）

1. 运行 `{{RELAY}} pickup <项目>`。它打印上下文和到达清单。
2. 按到达清单（post）逐项完成，同样遵守下一节的命令块规则。
3. 读项目的 `AGENTS.md`、`HANDOFF.md`，以及台账里的下一步。
4. 运行 `{{RELAY}} arrive <项目>`。
5. 告诉用户：原来的线程留在原设备。现在是读摘要开出来的新线程，不是原线程的恢复。

## 命令块怎么处理

每个命令块都带有 kind，按下面处理：

- 只读：可以直接执行。
- 只改本机：先把命令给用户看，得到同意后再执行。项目自己的规则更严时，从严执行。
- 写入远程：绝不执行，原样交给用户，由用户自己在自己的权限下运行。

## 三条硬规则

- 不执行任何写入远程的命令，例如 `git push`。`git fetch` 只读取远程、不改动它，出现在「只改本机」的命令块里时按那一类处理：先给用户看，同意后执行。
- 不读取、不复制凭据文件：`auth.json`、`.env`、`.claude.json`、私钥。只能检查它们是否存在，不能打开，也不能写进台账或摘要。
- 不把 HANDOFF.md 或台账记录说成「恢复了 Session」。本地 Session 只能在原设备原样恢复。

## 与 Claude Code、Antigravity 共用台账

- 其他代理登记的 Session、备注，在这里也能看到；这里登记的，它们也能看到。
- 不要删除或改写不是自己登记的 Session 条目。只对自己登记的条目使用 `session add` 和 `session rm`。
- 看台账用 `{{RELAY}} status`；需要 Session 列表时用 `{{RELAY}} sessions <项目>`。
